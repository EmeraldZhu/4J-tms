# Tenant Management System (4J-TMS)

Welcome to the 4J-Tenant Management System (4J-TMS), a modern web application designed for property owners and tenants. Built with Vue 3 and powered by Vite, 4J-TMS offers a seamless experience for managing properties, tenants, maintenance requests, and notices.

## Features

- **Authentication**: Secure login and registration for property owners and tenants.
- **Property Management**: Owners can add, view, edit, and delete their properties. They can also view detailed information for each property.
- **Tenant Management**: Owners can invite new tenants, view tenant details, and remove tenants from their properties.
- **Maintenance Requests**: Tenants can submit maintenance requests, viewable by property owners.
- **Notice Board**: A platform for owners to post notices for tenants.

## Technologies

- **Frontend**: Vue 3, PrimeVue
- **Backend**: Firebase
  - Authentication
  - Firestore Database
  - Cloud Storage

## Project Structure

- `src/`: Contains the main source code of the Vue.js application.
- `src/assets/`: Contains static assets like images, logos, and fonts.
- `src/components/`: Contains reusable Vue components used throughout the application.
  - `src/components/layouts/`: Contains layout components for different user dashboards (owner, tenant).
- `src/views/`: Contains Vue components that represent different pages or views of the application.
  - `src/views/auth/`: Components related to authentication (login, registration, password reset).
  - `src/views/owner/`: Components specific to the property owner's dashboard and features.
  - `src/views/tenant/`: Components specific to the tenant's dashboard and features.
- `src/router/`: Contains the application's routing configuration using Vue Router.
- `src/store/`: Contains the Vuex store setup for state management.
- `src/services/`: Contains services like Firebase configuration and interaction logic.
- `public/`: Contains static assets that are directly served by the webserver, like `index.html` and favicons.
- `dist/`: Contains the production-ready bundled files, typically generated by the build process.

## Contributing

We welcome contributions to 4J-TMS! Here's how you can help:

### Reporting Issues

- **Bug Reports**: If you find a bug, please open an issue on GitHub. Include a clear title, a detailed description of the issue, steps to reproduce it, and your environment details (browser, OS).
- **Feature Suggestions**: If you have an idea for a new feature or an enhancement to an existing one, please open an issue to discuss it. Provide a clear description of the proposed feature and its benefits.

### Pull Request Process

1.  **Fork the repository**: Click the "Fork" button at the top right of the repository page.
2.  **Create a new branch**: For your feature or bug fix (e.g., `feature/your-feature-name` or `fix/issue-number`).
    ```bash
    git checkout -b feature/your-feature-name
    ```
3.  **Commit your changes**: Make your changes and commit them with clear and descriptive messages.
    ```bash
    git commit -m "feat: Implement the new feature"
    ```
4.  **Push your changes**: Push your changes to your forked repository.
    ```bash
    git push origin feature/your-feature-name
    ```
5.  **Submit a pull request**: Open a pull request from your forked repository's branch to the `main` branch of the `4J-TMS/main` repository. Please provide a detailed description of your changes in the pull request.

### Coding Style

Please try to follow the existing coding style for consistency. We use Prettier for code formatting (though not strictly enforced in CI yet). Aim for clear, readable, and maintainable code.

### Setting up Development Environment

To get started with development, you'll need to set up the project locally.
1.  Ensure you have Node.js and npm installed.
2.  Clone your forked repository.
3.  Install the necessary dependencies:
    ```bash
    npm install
    ```
4.  Start the development server:
    ```bash
    npm run dev
    ```
    This will typically start the application on `http://localhost:3000`. For more details, refer to the [Project Setup](#project-setup) section.
